# Cost Revision: Assuming Extremely Cheap / Unlimited LLM Tokens

Bottom line: cheap tokens slash **code scaffolding, support, and paperwork** costs, but they do **not** remove IRS testing or liability. You still need a deterministic tax engine that passes ATS exactly.

## Revised year-1 ranges (with heavy LLM leverage)

| Scope | Before | With cheap unlimited tokens |
|---|---|---|
| MVP: 1040-only, 1 state, MeF e-file | $75k–$250k outsourced / $200k–$500k in-house | **$25k–$100k** (small team or founder + AI coding + CPA review) |
| Competitive consumer app | $500k–$2M+ | **$200k–$700k** |
| Pro / enterprise | $1M–$5M+ | **$500k–$2M** |
| Yearly keep-alive | $100k–$600k+ | **$50k–$250k** for small scope |
| Token cost itself | — | **$500–$5k/yr** even at heavy use — negligible |

Savings come from labor, not IRS fees (which were already $0).

## What gets much cheaper

1. **Boilerplate + MeF XML plumbing** — schemas, parsers, acknowledgement handling, retransmit logic. LLMs are excellent here: 40–60% faster.
2. **Test harness generation** — turn IRS ATS test returns + Pub 4164 business rules into scripted regression tests automatically.
3. **Yearly diff work** — feed last year vs new year pubs/schemas, have the model draft the code diff + changelog for a human to approve.
4. **Support** — biggest win. IRS Direct File data showed 80%+ of scale cost is support. AI chat + retrieval over your own help center can deflect 60–80% of routine "where is my refund / error 1234" tickets. Still keep humans for edge cases.
5. **Doc extraction + onboarding** — W-2/1099 photo import, plain-English explanations, error-code translation.

## What does NOT get cheaper

1. **ATS pass/fail** — IRS checks exact calculations + valid XML. An LLM guessing a refund amount fails. You need a deterministic rules engine with tests.
2. **CPA/EA verification** — someone licensed must sign off on tax logic. Unlimited tokens don't transfer liability.
3. **EFIN / suitability / state approvals** — human legal process, 4–8 weeks, background checks.
4. **Security audits + hosting** — SOC 2, pen test, PII controls still cost $25k–$100k/yr. No LLM discount.
5. **Liability for hallucinations** — a wrong deduction generated by an LLM is your bug in the IRS's eyes.

## The one rule

**Keep LLMs out of the math path.** All tax math lives in a deterministic rules engine (this repo's `tax-engine/`); the LLM may call it as a tool but never computes. An eval harness of known-answer returns blocks deploys on any mismatch — unlimited tokens make hallucinations cheaper to produce, not less liable. A wrong refund is still your bug.

## Recommended architecture with unlimited tokens

- **Deterministic core**: handwritten or strictly-reviewed rules for every calculation (`tax-engine/`). No LLM in the math path. LLM may *call* the core as a tool, never replace it.
- **LLM shell**: UX copilot, form explanations, document intake, support bot, code assistant for devs.
- **Eval harness**: every prompt + model change runs against known-answer returns (your ATS corpus). Block deploys on mismatch.
- **Human-in-loop**: CPA reviews all yearly logic diffs; support escalation path for anything involving money, identity, or filing submission.
- **Logging**: log model version + prompt + engine version per return so you can prove what computed what.

## How I'd spend the savings

Don't pocket all of it. Reinvest ~30% into:
- 2x more regression tests (auto-generated edge cases: married filing jointly + credits + multi-state)
- Better error recovery (MeF reject codes → one-click fixes)
- Security hardening + audit prep
- Better state-engine tooling — verification is the bottleneck now, not writing code

With cheap tokens, a 2–3 person team (1 full-stack dev, 1 tax analyst/CPA part-time, 1 QA/support) can ship a credible 1040 MVP in 3–6 months. The blocker shifts from "writing code" to "verifying correctness and passing ATS."
